## [Unreleased]

### Changed
- The Android target ships a bundled HarfBuzz 14.3.0 shaping backend, built from upstream revision `4c2aa804671d7276e8a0eb95da07202ead05c843` with NDK `30.0.15729638` for `arm64-v8a` and `x86_64` and published as `org.graphiks:kffi-harfbuzz-android` with its `kffi-harfbuzz-android-native` payload. The shared Android library floor is raised from API 24 to API 28 — a deliberate breaking change for API 24–27 consumers. The public shaping entry points are renamed without aliases: `JvmHarfBuzzShapingBackend` → `HarfBuzzShapingBackend`, `JvmPreparedFontCachePolicy` → `PreparedFontCachePolicy`, and `JvmPreparedFontCacheUsage` → `PreparedFontCacheUsage`, and the shaping binding coordinate becomes the multiplatform `org.graphiks:kffi-harfbuzz`. Android now declares `SHAPING` present in the portable capability matrix; glyphs, clusters, advances, positions, GDEF ligature-caret facts and typed errors are unchanged.
- The iOS target ships a bundled HarfBuzz 14.3.0 shaping backend, built from upstream revision `4c2aa804671d7276e8a0eb95da07202ead05c843` and statically linked through cinterop for `iosArm64` (device) and `iosSimulatorArm64` (simulator), published as `org.graphiks:kffi-harfbuzz-iosarm64` and `org.graphiks:kffi-harfbuzz-iossimulatorarm64`. iOS now declares `SHAPING` present in the portable capability matrix with the `bundled-harfbuzz` profile, so no current platform is left without a bundled shaping backend. Glyphs, clusters, advances, positions, GDEF ligature-caret facts and typed errors are unchanged, and the iOS simulator suite reproduces the frozen JVM-oracle goldens byte for byte.
- `:kalligraphie:raster-cpu` no longer hosts the composition conformance tests or the `rasterDumps` task: `OutlineConformanceTest`, `PaintConformanceTest`, `BitmapConformanceTest`, `ComposedLineDumps`, `GlyphSheetDumps` and the PGM/PPM canvas helper are absorbed by the non-published `:kalligraphie:e2e` module as golden scenes, the opt-in dump moves to `:kalligraphie:e2e:e2eGoldenDumps`, and the `raster-cpu` README plus the bilingual `raster-cpu` guides point at the new module. Fingerprints are unchanged: the migrated scenes reproduce the retired conformance digests and dump bytes byte for byte. The rasterizer itself, its unit tests, the logo seal and the platform font journeys are untouched.
- The portable outline IR gains an additive `GlyphOutlineIR.Command.CubicTo` and `GlyphOutlineCommand.CubicTo` for cubic Bézier segments, plus matching canonicalization, destructuring and non-finite rejection. Recompile consumers with exhaustive `when` handlers over these sealed types; move, line, quadratic and close behaviour is unchanged.
- Bitmap capability discovery is conservative and face-wide: every declared strike of a route must be structurally valid, one malformed unselected strike withdraws the route, and scan budgets for compressed and decoded bytes accumulate across all declared strikes while materialization applies per-strike budgets; duplicate declared strikes are rejected with the route-specific duplicate-strike failure when requested and withdraw the route during capability discovery.
- The canonical portable bitmap profile fingerprint changes: the strike token now carries the exact bit depth, so regenerate persisted profile fingerprints for every bitmap profile, including profiles whose declared parameters did not otherwise change (previously schema-1). Bitmap representation schema version 2 replaces version 1: `BitmapStrike` appends a required `bitDepth`, `BitmapLimits.maxBitmapTableBytes` becomes `maxSourceTableBytes`, and `BitmapProfile` defaults to schema version 2. Recompile consumers that construct these values, pass the exact strike bit depth (1 for the existing EBLC/EBDT monochrome route), and expect `font.unsupported-representation-profile` for version 1 bitmap profiles; existing monochrome glyph results are unchanged.
- Bitmap resource-bound breaches are now terminal instead of representation-local: a `BitmapResourceLimitExceeded` aborts the calling resolution instead of falling back to another accepted profile or font, unlike the generic `ResourceLimitExceeded` still used by the outline, SVG, and paint readers.
- The optional Apple module uses dedicated kffi CoreText bindings and Darwin system-information access instead of declaring native frameworks, symbols and layouts locally; font certification, resource ownership, budgets, cancellation and public leases retain their existing contracts.
- The JVM HarfBuzz shaping backend uses the published `org.graphiks:kffi-harfbuzz-jvm` binding instead of declaring native library loading, symbols, signatures, memory layouts and owners locally. Glyphs, clusters, advances, positions, GDEF ligature-caret facts and typed errors are unchanged; the native distribution provenance now names the kffi artifact while keeping the same binary digest, upstream source revision and build chain.
- macOS directory capture retains existing Kotlin call defaults but appends examination/diagnostic options and cancellation parameters: recompile consumers because the JVM constructor/factory entry points changed. Captures refresh explicitly into isolated generations.
- Font captures accept a trailing optional shared cache scope; recompile JVM consumers using changed factory/constructor signatures. Existing Kotlin calls retain their defaults and CoreText retention stays disabled by default.
- Paint schema 3 appends interpolation parameters to `GlyphPaintColorLine` and `PaintGraphProfile`, and three SVG transport bounds to `PaintGraphLimits`: recompile consumers using the changed JVM constructors or generated copy signatures, handle `PathClip` and the new interpolation enums, and regenerate persisted profile fingerprints even for schema 1 or 2. Historical COLR interpolation defaults are preserved; see the bilingual font-management migration notes.
- Static COLR v1 expands paint constructors, `PaintGraphLimits` generated `copy` signatures and sealed/enum cases: recompile consumers, update exhaustive handlers, never persist enum ordinals, and regenerate persisted profile fingerprints, including schema 1. Ordinary recompiled Kotlin constructor calls retain defaults; this is not JVM binary compatibility. Empty-group rejection now occurs when constructing schema-1 `GlyphPaintIR`, not `Group` alone; see the font-management migration notes.
- FontMaterializationCachePolicy now uses structured per-face/per-catalog budgets: generated Kotlin copy/destructuring operations are source- and binary-incompatible with the former byte-only data class; migrate to perFace/perCatalog and recompile consumers that used the old generated operations. The historical byte-only constructor and getter remain available.
- `FontError.CertificateNotInLayout` extends the sealed error surface used by the new font-asset handoff route. Add an arm when recompiling exhaustive Kotlin `when` handlers; existing method and JVM signatures remain available, but an already compiled exhaustive handler can throw `NoWhenBranchMatchedException` if this new member reaches it. Existing calls do not automatically emit this error.
- Kotlin 2.4.0 → 2.4.10
- Gradle 9.5.0 → 9.6.1
- Added blocking pull request policy checks aligned with `CONTRIBUTING.md`.
- Legacy `font/` sources are retained for reference but excluded from Gradle project aggregation, API documentation, and CI.
- The documentation site now embeds the API reference for the Kalligraphie modules.

- Variable font metrics on the portable routes. `:kalligraphie:font:sfnt` extends the shared `VariationStoreEvaluator` so a format-1 `ItemVariationStore`'s per-`ItemVariationData` delta rows are decoded and interpolated at a location (the `longWords` bit selects int32/int16 word deltas and the remainder are sign-extended int8), and adds `HvarReader`, `VvarReader` and `MvarReader` beside `GvarReader` in `org.graphiks.kalligraphie.font.sfnt.variation`, plus a shared `DeltaSetIndexMap` reader and `MetricVariationLimits`. `:kalligraphie:font:scaler` threads the instance's normalized axes through `PreparedTrueTypeFont.readGlyphMetrics`/`readVerticalGlyphMetrics` into `MetricsReader`/`VerticalMetricsReader` (trailing defaulted delta parameters), reads `HVAR`/`VVAR`/`MVAR` lazily per prepared face, keys the horizontal deltas on the `USE_MY_METRICS` metrics glyph, falls back to the metrics-source glyph's `gvar` phantom deltas when `HVAR`/`VVAR` are absent, and adds `PreparedTrueTypeFont.readFontMetrics`. `:kalligraphie:font:core` passes `FontInstanceKey.geometry.normalizedAxes` at `metrics`/`verticalMetrics` and implements the previously defaulted `FontInstance.fontMetrics()` on `TrueTypeFontInstance` from `OS/2` (with `hhea` fallback), `post` and `MVAR`. The priority is `HVAR`/`VVAR` then `gvar` phantom points then `hmtx`/`vmtx`; horizontal side bearings are adjusted only when the `HVAR` `lsb`/`rsb` mapping is present (the specification requires a mapping for side-bearing variation, so with none the `hmtx` side bearing is retained, unlike fontTools `varLib.instancer` which recomputes it from the varied outline), and the vertical phantom convention is `verticalAdvanceDelta = topY - bottomY`, re-validated against the OpenType chapter and fontTools. At normalized `wght = 1.0` the audited `NotoSansJP-VerticalFixture.ttf` glyph `A` advances `574 + 86 = 660` (`HVAR`) with an unchanged `lsb = 11`, the vertical advance stays `1000` (no `VVAR`, zero phantom delta), and `fontMetrics()` returns `(880, -120, 0, -125, 50, 543, 733)` from `OS/2`/`post` (no `MVAR`). New typed codes: `font.variation.unsupported-hvar-version`/`unsupported-vvar-version`/`unsupported-mvar-version` and `font.variation.invalid-hvar`/`invalid-vvar`/`invalid-mvar`; the embedded store keeps `unsupported-store-format`/`truncated-store`/`invalid-store`, and bounds breaches reuse `font.resource-limit-exceeded`. This is additive at call sites: the metric readers and `PreparedTrueTypeFont` gained trailing defaulted parameters, and `FontInstance.fontMetrics()` was already declared as defaulted surface. `VariationStoreLimits`'s constructor, `VariationStoreEvaluator.read`'s signature, and the public `PreparedTrueTypeFont.readGlyphMetrics`/`readVerticalGlyphMetrics` gained trailing defaulted parameters: recompile consumers that call the changed JVM constructors, `VariationStoreEvaluator.read`, or those two public methods (source-compatible, not JVM binary-compatible). Native bridges remain default-only; `STAT` reading, `avar` v2, `cvar`, `VARC` and the fingerprint-regenerating profile limit fields remain deferred, as do the §8 `maxVariationTableBytes`/`retainedBytes` cache-budget billing of the decoded metric tables. The shaping sub-plan now binds the HarfBuzz **horizontal** metric cross-check (see the shaping-at-the-instance entry below); the vertical advance and the specification's bounds remain unbound. Coverage remains partial: `VVAR` and `MVAR` are exercised only against synthetic bytes because no real fixture carries them, the composite metrics-source plus `gvar`-phantom (no-`HVAR`) horizontal fallback path is code-correct but still untested, the `HVAR` `lsb`/`rsb` and `VVAR` `tsb`/`bsb` mapping-present paths are reader-level only (so the scaler's non-zero side-bearing delta path is untested), and the synthetic variable CFF2 fixture's `HVAR` store declares no regions and no item deltas, so fontTools confirms its glyph `A` advance stays `1000` at `wght = 1.0` and there is no varied advance to assert through the CFF2 metric route. The default font-wide metrics prefer the `OS/2` `sTypo*` fields over `hhea` and deliberately ignore the CSS `USE_TYPO_METRICS` selection bit, so a font whose `OS/2` and `hhea` disagree returns the `OS/2` values. A present-but-empty delta-set index map means the implicit glyph-index identity rather than delta-set zero, matching HarfBuzz. `MVAR` value records wider than the eight-byte minimum are skipped stride-wise for forward compatibility, and `FDSelect` format 4 remains unsupported. - Variable COLR v1 colour on the portable route. `:kalligraphie:font:sfnt` now captures the COLR v1 header's `VarIndexMap`/`VarStore` offsets, parses the table's format-1 `ItemVariationStore` and shared `DeltaSetIndexMap` through the existing evaluator and reader (no second format-1 parser or index-map reader), adds `ColrV1Variation` to address per-field `VarIndexBase + ordinal` deltas, and applies them in each field's raw fixed-point/integer space — `PaintVarSolid`, the `PaintVar*` gradient paints with their `VarColorLine`, the variable transform paints (`PaintVarTransform`, format 13, via `VarAffine2x3`, and the `PaintVar*` translate/scale/rotate/skew variants via their inline variation fields), and the variable `ClipBox` format 2. `:kalligraphie:font:scaler` exposes `PreparedTrueTypeFont.orderedVariationAxes` and `:kalligraphie:font:core` passes the instance's `FontInstanceKey.geometry.normalizedAxes` into `ColrV1Reader.read`, so a non-default selection changes the resolved `GlyphPaintIR`. A store axis-count mismatch fails with the new `font.variation.invalid-colr`, as does the out-of-range `VarIndexMap`/`VarStore` offset guard on the internal `readColrVariation` entry point — a defensive check for a direct caller, since the integrated `ColrV1Reader.readIndexes` range-checks both header offsets first and reports `font.invalid-font-data`; the embedded store keeps `unsupported-store-format`/`truncated-store`/`invalid-store` and bounds reuse `font.resource-limit-exceeded`. The default instance and non-variable COLR fonts are bit-identical: the store is parsed only when the location is non-zero, and it is parsed once per render asset — the `ColrV1Data` the asset already owns, keyed by the full instance — rather than per face or generation. `ColrV1Reader.readColrVariation` honours a cancellation token but checks it before parsing, and the core preparation path passes none today, mirroring the other non-cancellable lazy table reads; the per-glyph paint walk stays cancellable. Additive at call sites: `ColrV1Reader.read` gained trailing defaulted `orderedAxes`/`variationLimits`/`storeLimits`/cancellation parameters and `ColrV1Data`'s internal constructor gained trailing defaulted fields, so existing Kotlin calls keep compiling; recompile consumers that call the changed JVM signature (source-compatible, not JVM binary-compatible). Known, deliberate limitations: a variable radial gradient whose applied deltas drive a radius below zero fails as invalid font data rather than being clamped (the specification permits a negative radius after deltas; the paint model requires non-negative radii), and a COLR paint with an unrecognized format fails through the unsupported-representation path rather than being ignored as the specification allows, so a font that adds a future paint format fails rather than degrading. The variable clip box evaluates in floating point and rounds outward so the box never shrinks (floor toward -infinity, ceil toward +infinity); the reversal check runs on the rounded integers, so a sub-unit float reversal that rounds outward to a non-reversed box is accepted while a reversal of one unit or more still fails. Native bridges remain default-only; `STAT`, `avar` v2, `cvar`, `VARC`, the fingerprint-regenerating variation profile fields and the §8 `maxVariationTableBytes`/`retainedBytes` cache billing remain deferred. Coverage: the audited synthetic `KalligraphieVarCOLRv1.ttf` exercises `PaintVarSolid`, `PaintVarLinearGradient` with a `VarColorLine`, `PaintVarTranslate` and variable `ClipBox` format 2 at `wght` 400/650/900; the `PaintVarRadialGradient`/`PaintVarSweepGradient` and `PaintVar*` scale/rotate/skew variants share the same accessors and are pinned against the fontTools field table but are not yet fixture-exercised. The variation-location parameter consolidation remains a recorded follow-up (see the metric entry above).

- Portable CFF1 (Type 2 charstrings) and CFF2 cubic outline routes. `.otf` with a `CFF ` table and CFF2 faces are parsed and materialized as `ScalerGlyphOutline` cubic contours with bounded points/contours, cancellation and typed refusals; `.otf` is accepted only when it carries a real CFF/CFF2 table. CFF1 supports local/global subroutines with bias, hint and hint-mask operators, the move/line/curve/flex operator families, arithmetic and transient operators, charsets 0/1/2, CID-keyed Font DICTs (`FDArray`/`FDSelect`) and the deprecated `endchar` accent composition through StandardEncoding. OTC collections carrying CFF faces are captured. Audited real-font fixtures cover CFF1 and static CFF2, and a fontTools-generated outline oracle covers CFF1 and the synthetic variable CFF2 fixture.
- sbix version 1 colour strikes with `'png '` graphics (version 1, bit 0 of the flags field set, reserved flag bits zero) selected by the exact `ppem` with no neighbouring-size substitution, origins and advances normalized from design units to strike pixels with round-half-away-from-zero, `'dupe'` records resolved to the referenced glyph's image within the same strike, and advances resolved from `hhea`/`hmtx` without requiring `glyf`; `'jpg '`, `'tiff'`, `'pdf '`, and `'mask'` remain unsupported.
